# ModuleRoutingMap — Карта маршрутизации звонков

Интерактивная read-only схема входящих и исходящих маршрутов звонков для MikoPBX, построенная на [React Flow](https://reactflow.dev/). Провайдеры, DID-маршруты, расписания, IVR-меню, очереди и внутренние номера автоматически собираются из текущей конфигурации АТС и отображаются в виде кликабельного графа — администратор видит всю логику обработки звонка за пару секунд, а не за шесть переходов между страницами настроек.

![Карта маршрутизации — входящие](docs/IncomingExample.png)

## Зачем это нужно

- **Весь путь звонка на одном экране.** Провайдер → DID → расписание → IVR → очередь → внутренний номер собираются в единый граф. Больше никаких «а в какое IVR попадает этот номер по выходным?».
- **Никакой настройки.** Модуль читает штатные таблицы MikoPBX — нет ни своих БД, ни ручного редактирования диаграмм. Жмёте *Обновить* — картинка соответствует реальной конфигурации.
- **Кликом — на нужную страницу.** Каждый узел диаграммы — это ссылка на соответствующую страницу админки (провайдер, маршрут, IVR, очередь, номер), так что схема одновременно служит навигатором.
- **Read-only по дизайну.** Модуль ничего не генерирует, не правит Asterisk и не пишет в таблицы MikoPBX. Безопасно ставить на прод.
- **Два представления — две задачи.** Вкладка *Входящие* показывает, как внешние звонки доходят до внутренних абонентов; вкладка *Исходящие* — какие префиксы уходят через какого провайдера.

## Возможности

- Две вкладки: **Входящие** (провайдеры → маршруты → расписания → IVR/очереди/номера/конференции/приложения) и **Исходящие** (правила набора → провайдеры)
- Авто-раскладка через [dagre](https://github.com/dagrejs/dagre) — узлы не перекрываются даже на АТС с сотнями маршрутов
- Свой визуальный стиль для каждого типа узла: провайдер, входящий маршрут/DID, расписание, IVR, очередь, номер, конференция, приложение, голосовая почта, внешний номер
- Клик по узлу открывает соответствующую страницу админки (`node.data.href`)
- Pan, zoom, fit-view и мини-карта — «из коробки»
- Кнопка **«Обновить»** в каждой вкладке — перезагружает граф без перезагрузки всей страницы
- Встроенная легенда показывает все типы узлов, реально присутствующих на текущей диаграмме
- REST API v3 (read-only) возвращает сырой `{ nodes, edges }` — можно скормить во внешние инструменты аудита
- Самодостаточный IIFE-бандл (~600 КБ, в нём уже React, ReactDOM, React Flow и dagre) — никаких CDN, работает на air-gapped инсталляциях

## Установка

### Из маркетплейса MikoPBX

1. Откройте веб-интерфейс MikoPBX.
2. Перейдите в **Модули** → **Маркетплейс**.
3. Найдите **«Карта маршрутизации»** и нажмите **Установить**.
4. Включите модуль на странице **Модули** → **Установленные**.

### Ручная установка

1. Скачайте свежий `.zip` со страницы [Releases](https://github.com/mikopbx/ModuleRoutingMap/releases).
2. В MikoPBX зайдите в **Модули** → **Установленные** → **Загрузить модуль** и выберите архив.
3. Включите модуль.

## Использование

1. Откройте **Модули → Карта маршрутизации**.
2. По умолчанию открывается вкладка **«Входящие»** — вы видите граф всех точек входа и куда они приземляются. Перетаскивайте холст для панорамирования, крутите колесо для зума, двойной клик фокусирует узел.
3. Переключитесь на **«Исходящие»**, чтобы увидеть, как внутренние номера попадают к каждому провайдеру через правила набора.
4. Клик по узлу открывает соответствующую страницу админки (провайдер, маршрут, IVR, очередь, номер, …) в той же вкладке.
5. Если вы поправили маршрутизацию в другом разделе кабинета, нажмите **«Обновить»** — граф перезагрузится без полного reload страницы.

> **Важно.** Диаграмма строится **только по данным, которые есть в UI MikoPBX**. Кастомный диалплан, override-файлы `extensions_custom.conf`, хуки сторонних модулей и контексты, генерируемые в рантайме, на схему не попадут. Для сильно нестандартных конфигураций сверяйтесь через CLI Asterisk.

## REST API v3

Авто-обнаружение через PHP 8 атрибуты. Все эндпоинты под `/pbxcore/api/v3/module-routing-map/`. Авторизация: localhost или Bearer-токен.

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| GET | `graph:incoming` | Ориентированный граф входящей маршрутизации (провайдеры → маршруты → расписания → IVR/очереди/номера) в формате `{ nodes, edges }` |
| GET | `graph:outgoing` | Ориентированный граф исходящей маршрутизации (правила набора → провайдеры) в формате `{ nodes, edges }` |

Формат ответа:

```json
{
  "nodes": [
    { "id": "provider-1", "type": "provider", "data": { "label": "SIP-Trunk-Megafon", "href": "/admin-cabinet/providers/modify/1" } },
    { "id": "route-42",   "type": "route",    "data": { "label": "+74951234567",      "href": "/admin-cabinet/incoming-routes/modify/42" } }
  ],
  "edges": [
    { "id": "e-provider-1-route-42", "source": "provider-1", "target": "route-42" }
  ]
}
```

Пример — получить входящий граф из скрипта:

```bash
curl -H "Authorization: Bearer $TOKEN" \
  https://pbx.example.com/pbxcore/api/v3/module-routing-map/graph:incoming
```

## Архитектура

```
PHP — построители графа         — Lib/GraphBuilder/  (Incoming/Outgoing + NodeFactory)
PHP — REST-контроллер           — Lib/RestAPI/Graph/ (авто-обнаружение через атрибуты)
PHP — web-контроллер админки    — App/Controllers/   (рендерит index.volt)
Исходники React Flow            — react-app/         (НЕ деплоится на АТС)
Готовый IIFE-бандл              — public/assets/js/vendor/react-flow.bundle.js  (~600 КБ)
Glue-код / fetch / mount        — public/assets/js/src/module-routing-map-index.js
Стили                           — public/assets/css/module-routing-map.css
```

PHP-сторона читает провайдеров, входящие маршруты, исходящие маршруты, расписания, IVR-меню, очереди, внутренние номера и конференции из стандартных моделей MikoPBX, после чего `NodeFactory` превращает каждую строку в типизированный узел графа. React-бандл — это самодостаточный IIFE, экспортирующий ровно один глобал:

```js
window.MikoRoutingMap.mount(htmlElement, graph, options?)
```

Glue-код тянет JSON с REST-эндпоинта, разворачивает обёртку `PBXApiResult` и зовёт `mount` отдельно для каждой вкладки. Кастомные React-компоненты для каждого типа узла лежат в `react-app/src/nodes/`.

## Сборка React-бандла

Артефакт маркетплейса уже содержит готовый бандл — конечному пользователю Node.js не нужен. Если вы правите React-исходники и хотите пересобрать:

```bash
cd react-app
npm install
npm run build
```

`npm run build` создаёт `../public/assets/js/vendor/react-flow.bundle.js` — один IIFE-файл, в который встроены React, ReactDOM, `@xyflow/react` и `dagre`. Готовый бандл коммитится вместе с правками исходников.

## Требования

- MikoPBX **2025.1.1+**
- PHP **8.4** (сервер; уже идёт в комплекте MikoPBX)
- Современный браузер с поддержкой ES2017 — бандл не транспилируется ниже этого уровня

## Ограничения

- Диаграмма отражает **только UI-конфигурацию**. `extensions_custom.conf`, ручные контексты и диалплан, генерируемый другими модулями в рантайме, не визуализируются.
- Это снимок конфигурации, а не лайв-карта звонков. Для оперативной картины используйте CDR / страницу «Активные звонки» MikoPBX.
- Только просмотр: правка диалплана прямо из диаграммы — за рамками задачи модуля.
